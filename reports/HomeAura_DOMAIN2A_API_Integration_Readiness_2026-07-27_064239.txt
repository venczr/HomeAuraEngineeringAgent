resolves only safe project-relative paths, enforces IFC and rooms-file size
limits, invokes the IFC importer with analyze_only enabled, performs no
project-data write, and sanitizes response diagnostics.

The ASGI app does not bind a network interface by itself. The known launchers
bind to localhost. Only the IFC preview route additionally enforces loopback
at the request layer. Existing health, project, snapshot, analyze, and room
routes do not have that route dependency.

6. PROPOSED MINIMAL READ-ONLY DOMAIN PREVIEW
======================================================================

Recommended endpoint:

POST /api/v1/rooms/domain/preview

Reason for a non-project-path route:

The DOMAIN-1 adapter must validate the exact project identity supplied in the
JSON envelope. A normal path parameter cannot faithfully carry every unsafe
path-shaped input, especially strings containing forward slashes, because
routing may reject or split them before the adapter sees them.

Recommended request JSON:

{
  "project_id": "Test_01",
  "rooms_payload": {
    "FormatVersion": "1.0",
    "DrawingName": "Test_01.dwg",
    "DrawingFullPath": "redacted-or-source-value",
    "Rooms": []
  }
}

Recommended request-envelope model:

DomainPreviewRequest

Fields:

project_id
Required string, minimum length 1, maximum length 128.

rooms_payload
Required JSON object containing the existing RoomExportReport-shaped payload.

Model policy:
extra fields forbidden.

Recommended success response:

HTTP 200
Response model: DomainDocument

The response should be the adapter result directly, including its existing
safe diagnostics. It must not add local file paths, report paths, tracebacks,
or source exceptions.

Proposed in-memory request flow:

1. Require the direct client address to be loopback.
2. Check a syntactically valid Content-Length when supplied.
3. Read request.stream incrementally.
4. Abort immediately when accumulated bytes exceed 10 MiB.
5. Decode JSON.
6. Validate DomainPreviewRequest.
7. Deep-copy or otherwise preserve the caller-owned mapping.
8. Call adapt_rooms_payload with rooms_payload and project_id.
9. Serialize the returned DomainDocument through response_model.
10. Return without reading or writing any project file.

Required request-size limit:

10 MiB, matching the existing rooms JSON limit used by IFC preview.

Critical implementation note:

Declaring a normal Pydantic body parameter and checking its size afterward is
not sufficient. FastAPI or Starlette may already have buffered and parsed the
entire body. The new endpoint must read and limit the stream manually before
model validation. The route can publish the request schema through explicit
OpenAPI requestBody metadata while using the manually bounded parser.

No global body-limit middleware is recommended for this first connection
because it would alter behavior of unrelated existing endpoints.

Recommended safe error contract:

Error body shape:

{
  "detail": {
    "code": "stable_machine_code",
    "message": "safe fixed message"
  }
}

Recommended statuses:

HTTP 400
Code: domain_payload_invalid
Use for malformed JSON or an invalid Content-Length representation.

HTTP 403
Code: loopback_required
Use the existing loopback rejection behavior.

HTTP 413
Code: domain_payload_too_large
Use when the declared or accumulated body exceeds 10 MiB.

HTTP 422
Code: domain_request_invalid
Use when the envelope fails validation.

HTTP 422
Code: domain_rooms_payload_invalid
Use when the legacy rooms payload cannot be adapted.

HTTP 422
Code: unsafe_identity_path
Use a fixed generic message. Do not echo the rejected project identity.

HTTP 500
Code: domain_preview_failed
Use a fixed generic message for unexpected failures.

Error-safety rule:

Do not return str(exception), Pydantic input values, traceback text,
absolute paths, file URIs, environment values, project-root paths, or raw
adapter input. Log only through the project's approved safe mechanism if
future logging is required.

8. WRITE, LEAK, AND REGRESSION THREAT REVIEW
======================================================================

Threat: accidental project write.

Control:
The proposed route accepts an in-memory rooms payload, does not resolve a
project directory, does not call the existing room POST route, does not call
analysis, and does not persist a DomainDocument.

Threat: source mapping mutation.

Control:
Tests must deep-copy the request mapping and assert equality after adaptation.
The actual Test_01 rooms mapping already passed this check during the audit.

Threat: path or secret leakage through validation errors.

Control:
Map adapter and validation failures to stable codes and fixed messages.
Do not echo project_id, DrawingFullPath, exception strings, or validation
input values.

Threat: unbounded JSON body.

Control:
Apply the 10 MiB streaming limit before JSON and Pydantic parsing.

Threat: non-loopback access.

Control:
Apply the existing direct-client loopback dependency to the new route. Do not
trust forwarded headers.

Threat: circular imports.

Control:
Keep the router independent from agent.api and register it one-way in
agent.api.

Threat: optional IFC dependency affecting DOMAIN preview.

Control:
The adapter imports existing models but does not load ifcopenshell. Keep the
future route free from run_import and other IFC execution.

Threat: regression in existing writable routes.

Control:
Do not modify their implementation. Add a new isolated router and assert all
existing route tests still pass.

Existing API findings that remain outside this minimal connection:

- Snapshot POST writes files and accepts a generic mapping.
- Analyze POST writes report and history files.
- Rooms POST writes canonical and history files.
- Some existing errors and responses contain absolute local paths.
- Most existing routes lack an explicit request-layer loopback dependency.
- No global request-body limit is present.

These findings do not block an isolated safe DOMAIN preview, but the new route
must not copy those patterns.
