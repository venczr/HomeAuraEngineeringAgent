25. РИСКИ
- Safety Gate и Tool Registry — новый код, использованный один живой день;
  22 unit-теста покрывают известные сценарии, но не являются
  доказательством отсутствия всех возможных обходов (например, символьные
  ссылки/junction points на Windows не тестировались отдельно).
- `run_allowlisted_build`/`restart_allowlisted_homeaura_service` с пустым
  allowlist создают ложное чувство полноты реестра инструментов — они
  существуют по имени, но не могут ничего сделать, пока кто-то не заполнит
  allowlist; это нужно помнить при дальнейшей разработке, не путать
  "инструмент существует" с "инструмент функционален".
- Telegram approval без реального inbound-канала означает, что сейчас
  ЛЮБОЙ реальный WAITING_APPROVAL таймаутится в "отклонено" без участия
  человека, если никто вручную не создаст файл решения — это безопасно
  (fail-closed), но не то же самое, что рабочий approval-процесс.
- `homeaura-manager` (`deep_manager`) по-прежнему не диагностирован по
  скорости — не является частью этого этапа согласно прямому указанию, но
  риск остаётся неустранённым для будущих этапов, которые захотят его
  использовать.
- Реальная runtime БД `homeaura_tasks.db` теперь содержит только 4
  реальных задачи из демонстрации этого этапа — это ожидаемо малый объём
  и не было нагрузочно протестировано.
