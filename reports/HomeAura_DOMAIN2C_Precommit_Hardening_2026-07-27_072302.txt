======================================================================
5. REQUEST.CLIENT AND HOST AUTHORITY
======================================================================

The existing direct Request.client loopback check remains mandatory.
Forwarded and X-Forwarded-For do not influence it.

The route now also reads raw request.scope headers and requires exactly one
Host before reading the body.

Accepted Host authorities:

localhost
localhost with a valid port
127.0.0.1
127.0.0.1 with a valid port
[::1]
[::1] with a valid port

localhost comparison is ASCII case-insensitive.

An optional port must contain only ASCII digits and have numeric value from
1 through 65535. No DNS lookup is performed.

The following are rejected with safe HTTP 403 loopback_required:

- missing Host;
- duplicate equal Host;
- conflicting duplicate Host;
- arbitrary domain;
- localhost.evil and other DNS-rebinding-shaped names;
- userinfo;
- whitespace or control characters;
- comma lists;
- trailing dot;
- zone-qualified IPv6;
- unbracketed IPv6;
- malformed or out-of-range port;
- integer, hexadecimal, octal, and zero-padded alternate IP forms;
- non-ASCII Host.

The supplied Host is not returned or logged.

Forwarded, X-Forwarded-For and X-Forwarded-Host cannot change an invalid
direct Host into an allowed authority.

Tests prove that rejected missing, duplicate, conflicting, arbitrary, and
rebind-shaped Hosts are handled before body receive and before
adapt_rooms_payload.

6. CONTENT-TYPE AND BROWSER-TO-LOCALHOST DEFENSE
======================================================================

Content-Type is read from raw request.scope headers and must occur exactly
once.

Allowed forms:

application/json
application/json; charset=utf-8

Media type, parameter name and charset comparison are case-insensitive.

Rejected before reading the body:

- missing Content-Type;
- duplicate equal Content-Type;
- conflicting duplicate Content-Type;
- text/plain;
- form data;
- multipart;
- any other media type;
- non-UTF-8 charset;
- additional or ambiguous parameters;
- non-ASCII header value.

Duplicate equal and conflicting Content-Type tests verify:

- HTTP 415 domain_content_type_invalid;
- receive is not called;
- adapt_rooms_payload is not called.

Simple browser form and no-CORS text/plain requests therefore cannot reach
JSON parsing. No CORSMiddleware is installed, and no permissive CORS behavior
was found.
