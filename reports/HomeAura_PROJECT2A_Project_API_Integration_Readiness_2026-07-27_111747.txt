9. CHOSEN MINIMAL PROJECT-2 API CONTRACT

Route:
POST /api/v1/projects/canonical/preview

Reason:

- read-only repository conventions use a final /preview segment;
- /api/v1/projects is the project API namespace;
- the static canonical segment does not conflict with legacy
  /{project_name}/snapshot, /rooms, or /analyze paths;
- no path project ID is needed because CanonicalProjectModel already carries
  the canonical UUID;
- no registered project directory is consulted.

Request:

The raw JSON body is CanonicalProjectModel itself, not a wrapper and not a
filesystem location.

OpenAPI:

The handler must accept Request for manual transport parsing and declare the
CanonicalProjectModel request schema via openapi_extra, matching the DOMAIN
preview pattern.

Success:

HTTP 200, application/json.
Response schema: CanonicalProjectModel directly.

Serialization:

Use canonical_json_bytes(validated_model) and a Response with
media_type="application/json". This yields sorted keys, compact separators,
UTF-8, preserved Unicode, finite JSON only, and deterministic bytes. The route
decorator still declares response_model=CanonicalProjectModel.

No response wrapper, timestamp, generated ID, inferred field, or readiness
change is permitted.

Parsing sequence:

1. Validate direct loopback client.
2. Validate exactly one strict local raw Host authority.
3. Validate exactly one application/json Content-Type.
4. Inspect raw Content-Length before reading.
5. Stream and count raw bytes with a 10 MiB maximum.
6. Pass the raw bytes to CanonicalProjectModel.model_validate_json.
7. Return canonical JSON bytes from the validated model.

Maximum body:
10 * 1024 * 1024 bytes.

Content-Length:

- missing: allowed; stream limit still applies;
- empty, signed, negative, nonnumeric, whitespace, comma-list: HTTP 400;
- any duplicate, including equal duplicate: HTTP 400;
- conflicting duplicate: HTTP 400;
- declared over limit: HTTP 413 before receive;
- actual streamed body over limit: HTTP 413.

Content-Type:

- exactly one application/json: accepted;
- optional single charset=utf-8: accepted;
- missing, text/plain, other parameter, malformed, duplicate/equal, or
  conflicting: HTTP 415 before receive.

Loopback:

- direct client must be an IP loopback;
- raw Host must be exactly localhost, 127.0.0.1, or [::1], optional valid
  decimal port;
- no DNS resolution;
- Forwarded/X-Forwarded-* never override direct client or Host;
- no CORS middleware.

Proposed fixed safe errors:

HTTP 400
code: project_payload_invalid
meaning: malformed Content-Length, UTF-8, JSON, duplicate key, non-finite
number, or non-object/model JSON syntax failure.

HTTP 403
code: loopback_required
meaning: direct client or raw Host is not an accepted local authority.

HTTP 413
code: project_payload_too_large
meaning: declared or actual raw body exceeds 10 MiB.

HTTP 415
code: project_content_type_invalid
meaning: required JSON content type is absent or invalid.

HTTP 422
code: project_model_invalid
meaning: strict CanonicalProjectModel validation failed.

HTTP 500
code: project_preview_failed
meaning: unexpected internal preview failure.

All errors use:
{"detail":{"code":"...","message":"fixed safe text"}}

No exception text, traceback, Pydantic input, project UUID, local path,
environment value, credential, equipment value, or user-supplied string may
be reflected.
