5. DEFECT REPRODUCTION BEFORE THE FIX

The reproduction used in-memory deep-copied fixtures, omitted
Room.SourceHandle and supplied two different synthetic path-shaped Code
values with the same final name for each path class.

Format | path class | result | same UUID | basename fallback
1.0 | Windows drive | UNSAFE | YES | YES
1.0 | POSIX | UNSAFE | YES | YES
1.0 | UNC | UNSAFE | YES | YES
1.0 | Windows device | UNSAFE | YES | YES
1.0 | file URI | UNSAFE | YES | YES
1.1 | Windows drive | UNSAFE | YES | YES
1.1 | POSIX | UNSAFE | YES | YES
1.1 | UNC | UNSAFE | YES | YES
1.1 | Windows device | UNSAFE | YES | YES
1.1 | file URI | UNSAFE | YES | YES

Cause:

_identity_records used _safe_identity_text for Room.Code. That helper is
correct for non-identity output but intentionally reduces an absolute
path to its final name. With SourceHandle absent, the reduced Code then
entered canonicalization and UUIDv5. Distinct paths sharing the final
name therefore produced one Room UUID.

The reproduction did not mutate its inputs and did not leak the raw
paths, but it silently collapsed identity. That result was unsafe.
