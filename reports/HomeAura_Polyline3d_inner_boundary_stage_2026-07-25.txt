2. РЕАЛИЗОВАННАЯ ПОДДЕРЖКА POLYLINE3D
========================================================================

Polyline3d используется только при одновременном выполнении условий:

1. PolyType = SimplePoly.
2. Отклонение исходных вершин по Z не превышает 1 мм.
3. Контур планарен по принятому Z-допуску.
4. Есть флаг AutoCAD Closed либо первая и последняя вершины совпадают
   в пределах допуска.
5. После нормализации остаётся не менее трёх различных вершин.
6. Последовательные дубликаты удалены.
7. Самопересечения отсутствуют.
8. Известен коэффициент перевода единиц DWG в метры.

Для Polyline3d сохраняются:

    SourceHandle
    SourceObjectType
    SourceLayer
    SourceVertices с исходными XYZ
    Vertices после нормализации
    OriginalClosedFlag
    LogicalClosureMethod
    ZDeviationDrawingUnits
    ZDeviationM
    IsPlanar
    Polyline3dType
    HasMagiCadData
    ContourAreaDrawingUnits2
    ContourAreaM2
    PerimeterDrawingUnits
    PerimeterM
    GeometrySource
    Diagnostics

Исходная повторная конечная вершина сохраняется в SourceVertices, но
удаляется из нормализованного Vertices. Направление нормализуется до
CCW. Для допустимой SimplePoly площадь берётся из точной формулы
XY-проекции прямых сегментов, а периметр — из точных координат.

3. ВЫБОР ГРАНИЦЫ
========================================================================

Рейтинг кандидатов:

    Tier 0:
        MAGIROOMBORDERS + MagiCAD-R + маркер внутри.

    Tier 1:
        MAGIROOMBORDERS без MagiCAD-R + маркер внутри.

    Tier 2:
        остальные валидные контуры с маркером внутри.

Внутри одного Tier учитывается абсолютное расхождение площади с
MagiCAD NetAreaM2. Слой 0 не может обойти валидную MagiCAD-границу
только из-за немного меньшего расхождения площади.

Если два лучших кандидата одного Tier равноправны в пределах допуска
рейтинга 0.01 м², Boundary не выбирается:

    boundary_selection_status = ambiguous

При этом все кандидаты экспортируются в boundary_candidates, а
предупреждение объясняет неоднозначность.

Расхождение строго больше 15% устанавливает:

    area_match_status = warning

Для выбранной Polyline3d устанавливается:

    geometry_status = provisional

9.2. Extension Dictionary объекта 101DA95
-----------------------------------------------------------------------

Ключ:

    MagiCAD-R

Xrecord содержит только три бинарных поля:

    FieldId 0x044D, payload E903
    FieldId 0x04BE, payload 01000000
    FieldId 0x04C0, payload 0000

В этом Xrecord не найдено:

    - массива XYZ;
    - площади 17.231460571289062;
    - толщины/отступа;
    - ссылки на отдельный внутренний контур.

Площадь NetArea присутствует в MagiCAD-R маркера 101DAA3:

    FieldId 0x051D = Float32 17.231460571289062

Следовательно, текущий MagiCAD-R объекта 101DA95 подтверждает
принадлежность MagiCAD, но сам по себе не даёт чистую внутреннюю
геометрию. Семантика служебных полей 0x044D/0x04BE/0x04C0 без
официальной схемы не угадывалась.

    X left:              153.178875534029 мм

    Y bottom:            152.750758553557 мм
    Y top:               3843.40652027231 мм

Если только для диагностики соединить эти четыре наблюдаемые линии,
получается прямоугольник:

    площадь:             17.321458486167927 м²
    разница с NetArea:   +0.089997914878865 м²
    разница:             +0.522288371937663%

Этот прямоугольник не существует в DWG как отдельный замкнутый объект.
Он не был записан в чертёж и не принят как Boundary.

Внутренние стороны габаритов четырёх AEC_WALL дают другой
диагностический прямоугольник:

    площадь:             17.197555816716342 м²
    разница с NetArea:   -0.033904754572720 м²
    разница:             -0.196760770408588%

Это также не сохранённый контур. Габариты AEC-объектов нельзя считать
универсальной чистой границей: на реальных планах влияют соединения,
скосы, криволинейные стены, колонны, шахты и правила учёта площади.

Итог поиска:

    - точный внутренний контур, равный NetAreaM2, в DWG не найден;
    - MagiCAD-R объекта 101DA95 не содержит декодируемую геометрию;
    - стеновые грани позволяют получить близкие, но разные результаты;
    - постоянный отступ на основании одного помещения применять нельзя.

10. РЕКОМЕНДАЦИЯ ПО НАДЁЖНОМУ ИСТОЧНИКУ ЧИСТОЙ ГЕОМЕТРИИ
========================================================================

Приоритетный источник:

1. Официальный MagiCAD API/Object Model для Room/Space, если он
   предоставляет уже рассчитанные boundary loops либо правила net
   floor area. Это лучший вариант, потому что NetAreaM2 рассчитана
   MagiCAD и хранится на маркере, но её геометрическое происхождение
   не сериализовано в 101DA95.

Надёжный технический fallback:

2. Нативная геометрия AEC_WALL через Autodesk AEC SDK/Object Enabler:
   получать реальные поверхности/грани стен, строить топологический
   замкнутый цикл по стороне маркера и выполнять геометрические
   операции с колоннами, шахтами и другими вычитаемыми объектами.
   Результат должен проверяться против NetAreaM2 и оставаться
   provisional при расхождении.

Дополнительный источник:

3. Линии граней MagiCAD wall-блоков можно использовать как кандидаты
   для топологической сборки, но не как готовую чистую границу: в
   Test_01 они не образуют сохранённый объект и дают площадь, отличную
   от NetAreaM2 на 0.09 м².

Текущий безопасный режим:

4. Использовать 101DA95 как предварительную MagiCAD-границу,
   сохранять NetAreaM2 отдельно, явно экспортировать расхождение и не
   применять автоматический offset.

11. КОМАНДЫ ДЛЯ ПРОВЕРКИ В AUTOCAD
========================================================================

1. Открыть копию Test_01.dwg. Исходный DWG не использовать для
   экспериментальной проверки.

2. Выполнить:

       NETLOAD

3. Выбрать:

       C:\AI\HomeAuraEngineeringAgent-temp-build\
       room-geometry-1.2.0.0\plugin\
       HomeAura.AutoCAD.Agent.dll

4. Выполнить read-only диагностику:

       HA_DISCOVER_ROOM_BOUNDARIES

Ожидается:

    кандидатов:          2
    валидных:            2
    101D22A:             LWPOLYLINE, слой 0, 20 м²
    101DA95:             Polyline3d, MAGIROOMBORDERS,
                         MagiCAD-R=True,
                         Repeated first/last vertex,
                         19.9266536521835 м²

5. Выполнить экспорт:

       HA_EXPORT_ROOMS

6. Проверить rooms.json:

       Boundary.SourceHandle = 101DA95
       BoundaryAreaM2 = 19.926653652183532
       MagiCadNetAreaM2 = 17.231460571289062
       geometry_status = provisional
       area_match_status = warning
       boundary_selection_status = selected

7. При необходимости отправки в API:

       HA_SYNC_ROOMS

Команды диагностики и экспорта не изменяют геометрию DWG.
