Validated points:

- git-filter-repo version 2.47 or newer is required for
  --sensitive-data-removal.
- --refs implies --partial and is not acceptable here because it can retain old
  refs and mix histories.
- --source/--target also implies partial processing, but the filter-repo manual
  explicitly states that separate source and target repositories avoid mixing
  old and new histories.
- --sensitive-data-removal normally gathers refs. The proposed --no-fetch is
  explicit, prevents this, and is also implied by partial mode. The explicit flag
  documents the offline boundary.
- a branch-only bundle can transport the independently verified one branch and
  all reachable Git objects; it does not carry LFS payloads.
- a bare clone copies branch heads directly to local heads and does not create
  refs/remotes/origin/*. The input must be checked for exactly one head, no main,
  tags, notes, replace refs, stash or reflogs.
- a bundle is not a local repository object directory and does not hardlink the
  original repository. If a local Git repository is substituted as a clone
  source, git clone --no-local is required.
- the rewrite uses separate disposable repositories, no GitHub remote,
  GIT_LFS_SKIP_SMUDGE set to 1, explicit --no-fetch and no --force.
