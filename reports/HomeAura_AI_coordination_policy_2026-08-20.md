# HomeAura — постоянное распределение работы между ИИ

Статус: обязательная инструкция для всех следующих этапов проекта тёплого пола.
Зафиксировано владельцем: 2026-08-20 23:46 MSK.

## Роль координатора Codex

Codex не проектирует раскладку в одиночку. Его работа:

1. Подготовить всем помощникам одинаковые исходные данные, геометрию, изображения, эталонные проекты и полный регламент.
2. Разделить задачи между внешними помощниками и следить, чтобы они не решали одну и ту же задачу вслепую.
3. Собирать точные координаты, расчёты и доказательства, а не принимать визуальные обещания.
4. Передавать результаты на независимую проверку.
5. Замораживать проектный артефакт только после прохождения всех обязательных проверок; при долге честно сохранять статус NO-GO/не готово.

## Роли помощников

- ChatGPT 5.6 Sol, режим «Очень высокий»: проектная стратегия, owner-style морфология, один точный кандидат и объяснение топологии.
- Kimi K3, максимальный доступный режим: независимый альтернативный кандидат, поиск пустот, тупиков, пересечений и более простой топологии.
- Claude/Claude Code CLI: независимый аудитор доказательств. CLI не должен доверять текстовому отчёту — он читает фактический `.homeaura.json`, координаты, diagnostics и тесты и заново воспроизводит метрики.
- Codex: только координация, сведение противоречий, постановка следующего узкого задания и контроль границы публикации.

Claude Code CLI ожидается доступным ориентировочно после 2026-08-21 00:41 MSK. При первом доступном запуске ему передаётся именно проверка доказательств последнего кандидата.

## Обязательный вводный пакет до начала любой работы

Каждый помощник до выдачи решения обязан получить и подтвердить понимание:

1. `HomeAura_owner_floor_heating_routing_rules_for_all_helpers_2026-08-20.md` полностью.
2. Оба эталонных PDF владельца и пояснение, какие особенности в них являются эталоном морфологии.
3. Чистый рендер текущего этажа/комнаты и диагностический рендер последней попытки.
4. Точную геометрию разрешённого BODY-домена, стен, окон, исключений, коллектора и портов.
5. Текущий исходный `.homeaura.json` и нативные diagnostics.
6. Явное предупреждение: кухонные пустоты из старых проектов не копируются. В новом проекте вся допустимая отапливаемая площадь должна быть покрыта трубой. Пустота допустима только как отдельная подтверждённая зона исключения; кухня сама по себе исключением не является.

Помощник сначала кратко пересказывает правила своими словами. Если пересказ неверен, координаты от него не принимаются.

## Что именно проверяет Claude Code CLI

Проверка должна быть read-only до вынесения вердикта и включать:

- идентичность входного SHA256 и точный diff относительно официального предшественника;
- одну непрерывную трубу каждого контура и честные BODY/TRANSIT ranges;
- отсутствие скрытой/подставленной длины и непроложенных Eurocone-хвостов;
- R80 по физически материализованной геометрии, а не по острой или условно скруглённой линии;
- отсутствие self/inter-circuit contacts с учётом наружного диаметра 16 мм;
- BODY в разрешённом домене, BODY-wall=0, turn-wall=0;
- только короткие перпендикулярные проходы TRANSIT через стены и только через подтверждённые места;
- шаг 200 мм в поле, три отдельные линии 100/200/300 мм у применимых наружных стен и окон, отсутствие U-разворотов 100 мм;
- физическое покрытие не менее 96%, максимальный пробел не более 200 мм, число проб >200 мм равно нулю;
- отсутствие необъяснимых пустот, включая кухню;
- длину каждого полного контура 40–80 м и разброс парных территорий не более 2 м;
- визуальное соответствие owner-style: компактная counterflow-улитка, локальная змейка только для остатка, без доминирующего общего меандра;
- честную границу: bounded-terminal не называется collector-continuous или installation-ready.

## Правило принятия

Ответ помощника без точных массивов координат, исходных файлов, воспроизводимых метрик и списка не пройденных ворот считается консультацией, но не доказательством. Публикация разрешается только после независимого воспроизведения Claude Code CLI и второго независимого review. Любой спор разрешается фактической геометрией и нативным анализатором, а не уверенным текстом модели.
