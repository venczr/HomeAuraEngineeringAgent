7. РЕШЕНИЕ ПО РАЗДЕЛЕНИЮ ОТВЕТСТВЕННОСТИ
Подтверждается модель, уже принятая (но не закоммиченная) на предыдущем
этапе и дословно совпадающая с целевой архитектурой задания:
- HomeAuraOrchestrator — единственный долгосрочный владелец task queue,
  SQLite task store, универсальной state machine, RAG, Safety Gate, tool
  allowlist, Command Runner, маршрутизации локальных моделей, облачной
  эскалации, Project Bridge, Codex Relay, Claude adapter, Telegram
  approval-решений, аудита, восстановления заданий. Из этого списка
  реально готовы: Project Bridge (конфигурация/state, НЕ browser/CDP),
  Codex Relay (contract+security+worker+hooks), Claude adapter, Telegram.
  Не готовы нигде: RAG, Safety Gate, единая state machine.
- HomeAuraLocalSupervisor — только health/process monitoring, watchdog,
  сбор внешних событий, уведомления, безопасный запрос перезапуска через
  Orchestrator. НЕ должен владеть очередью, RAG, Safety Gate, облачной
  маршрутизацией. РИСК к устранению: собственный Telegram-адаптер
  (supervisor/notifications/telegram_adapter.py) частично дублирует
  Orchestrator — требует явного решения, чей адаптер остаётся основным.
- HomeAuraEngineeringAgent/tools/local_supervisor — подтверждённый статус
  TEMPORARY PROTOTYPE в обоих отчётах; используется только для проверки
  Ollama-вызовов; расширение как отдельной системы запрещено — уже
  зафиксировано, менять не требуется.
