# HomeAura — Г-образная комната и дверные проходы

Выполнен новый синтетический стенд. **Положительные результаты: два независимых BODY-контура в Г-комнате и отдельная пара подводок через дверь.** Полное соединение этих подводок с BODY и коллектором пока не выполнено. Автоматического разбиения произвольной Г-комнаты также нет: две зоны заданы явно во входе.

## Г-образная комната

Контур комнаты: (0,0)→(4000,0)→(4000,3000)→(3000,3000)→(3000,7000)→(0,7000), площадь24 м². Разбиение: прямоугольник4000×3000 и повёрнутый прямоугольник3000×4000. Ограничения прежние синтетические: p200 на прямых с ограниченными BOX-зонами переходов, Rmin80/фактическиR100, OD16, surface-wall80, каждый контур≤80 м, coverage99% с radius250 и maximum-distance250.

| Вариант | Длина | Покрытие | Максимальное расстояние | Результат |
|---|---|---|---|---|
| Один контур UFH Designer | 95,455 м | Нижняя оценка96,889% | Интервал для максимума444,812..480,188 мм | Fail: длина и пробел |
| Два BODY-контура | 58,198 м каждый | Нижняя оценка100%, в обеих зонах | Верхняя оценка236,348 мм | TwoBodyCellsPass |

У пары BODY расстояние между осями контуров200 мм, до фактической стены100 мм. Внутренний стык зон не считается стеной. Проверены и вся Г-область, и покрытие каждой составляющей. Принятый max250 не означает более строгий owner max200; реальный дом не получает монтажный статус.

Для вогнутой области изменён способ численной оценки покрытия: отбираются **все клетки25 мм, пересекающие полигон**, даже если их центр находится снаружи. Расстояния от центров дают верхнюю оценку с половиной диагонали клетки и погрешностью дуг. Это сохраняет границу ошибки возле вогнутого угла; простая фильтрация grid nodes внутри комнаты этого не гарантировала. Для нижней оценки максимума в UFH-пробе половина диагонали также вычитается, поскольку некоторые центры снаружи.

UFH Designer действительно строит путь внутри этой Г-формы: 181 точка, из instrumented trace сохранены35 дуг; R/G1/OD проходят. Однако одного контура оказалось недостаточно по заданным численным условиям. Его точные терминалы и общая L-морфология отдельно не подтверждены — им не присвоен Pass задним числом.

## Дверь и поворот подхода

Две прямоугольные комнаты разделены стеной толщиной200 мм. Проём центрирован по y1500, первоначальная ширина900 мм. Оси проходят через дверь по y1400 и y1600; до двери предусмотрены повороты90° с R100. Все четыре конца и направления зафиксированы в fixtures.json до запуска.

Проверяются обе цепи целиком: schema, непрерывность, G1, R≥80, свои контакты, контакт между цепями, фактическая сплошная стена за вычетом проёма, граница доступного пола и пересечение полной толщины стены. Между отдельными цепями нет исключения «соседние участки одной трубы».

| Случай | Результат |
|---|---|
| Проём900 мм | DoorPairGeometryPass; ось–косяк350 мм |
| Проём377 мм | Pass; ось–косяк88,5 мм |
| Проём376 мм | Indeterminate; ровно88 мм без численного запаса |
| Проём375 мм | Fail; ось–косяк87,5 мм |
| Проём сдвинут на500 мм | Fail: маршрут попадает в сплошную стену |
| Проём закрыт | Fail |
| Между осями15 мм | Fail по OD16 |
| У дуги отсутствует R | Schema Fail |
| Дуга удалена, цепь разорвана | Fail |
| Пустая цепь | Schema Fail |

376 = 200 + 2×(80+16/2) — необходимая ширина **для этой фиксированной симметричной прямой пары**. Это не универсальная минимальная ширина двери и не доказательство физической непроходимости других раскладок. Пограничный Indeterminate блокирует экспорт.

## Проверки и ограничения

13 сценариев с ожидаемыми результатами прошли: 3 проверки Г-комнаты, включая межконтурную коллизию и путь снаружи области, и10 дверных случаев. UFH-проба сохранена отдельно. Независимый read-only review подтвердил расстояния, пороговые статусы и корректность upper-bound для вогнутой области. Он выявил необходимость проверять `room.covers(path)` и ранний отказ пустой/нечисловой схемы; исправления включены, повторный узкий прогон выполнен.

Нет готового solver для всех Г-форм, автоматического выбора разбиения, общего поиска подводок, единого графа от коллектора до каждого BODY, теплогидравлики и CAD round-trip. DoorPairGeometryPass не равен ValidRoomRoute. Экспорт во всех артефактах запрещён. Истёкшая авторизация Claude из предыдущего этапа не исправлялась и успешный Claude-аудит не заявляется.

Следующий практический блок — заранее резервировать общие подводки и соединять их с конкретными BODY-портами, затем повторно проверять **весь** полученный контур и его полную длину. Простое соединение уже готовых островков без повторной проверки недопустимо.

## Воспроизведение

В окружении Python/NumPy/Shapely предыдущего пакета:

```powershell
python complex-rooms/run.py
node complex-rooms/probe_ufh.mjs work/ufh-source complex-rooms
python complex-rooms/check_ufh.py
```

Для UFH нужен распакованный закреплённый source ZIP и npm dependencies по инструкции m1a-v2/REPRODUCE.md. Для картинки — matplotlib3.10.8 и complex-rooms/render.py. fixtures.json, координаты, результаты, журналы и хеши включены в пакет. Production-исходники HomeAura не изменены.
