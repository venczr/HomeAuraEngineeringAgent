# HomeAura — результат M1a и ограниченного M1b

9 сентября 2026. Только синтетический эксперимент; production-код не менялся.

**Решение: BUILD одного небольшого прямоугольного шаблона для проверенной задачи.** Ручной бифилярный эталон принят ограниченным независимым checker; опыт сохранения дуг UFH Designer успешен, но выбранная попытка адаптации его подключения дала наложение труб. Это достаточное основание продолжить малый собственный шаблон в данном эксперименте, не доказательство невозможности другой адаптации UFH Designer.

M1a закрыт **в явно ограниченном синтетическом контракте с BOX-зонами переходов**. M1b реализован как экспериментальный Python-шаблон. Общий Floor Engine, постоянный p200 на дугах, owner-style/монтажная готовность и CAD-интеграция не подтверждены. `export_allowed=false` во всех результатах, включая положительные.

## Неизменный контракт и ручной эталон

`m1a-v2/fixture.json` побайтно совпадает с исходным M1a fixture: SHA256 `875309ef5358973e3cc3387604d722b64ff43260c6213e2f188207c32e5fa2b3`. Комментарий о прежней змейке сохранён как историческая metadata; новая ручная улитка записана отдельно. Концы (200,100) и (3800,2900), обе касательные (+1,0), пределы покрытия и длины не подстраивались под UFH.

Подача проходит по вложенным прямоугольным уровням, обратка занимает промежуточные уровни и выходит через полосу вдоль левой и нижней границ. Центральное соединение — отдельная аналитическая полуокружность. Ручные координаты заданы в reference.py, checker их не импортирует.

## Что проверяет checker

Линии и дуги проверяются по реальным координатам: допустимые параметры, конечность, ортогональные прямые/четверть- и полуокружности, непрерывность, G1-касательные, радиусы, длина и концы. Для измерений хорды имеют sagitta ≤0,01 мм и длину ≤4 мм. Зазоры учитывают 0,01 мм для стены и 0,02 мм для пары кривых. На границе допуска правило возвращает Indeterminate, а не Pass.

OD-проверка через STRtree не пропускает целые соседние примитивы. Исключается только локальная окрестность по длине до32 мм; её применение ограничено проверенными G1 и R≥80 при OD≤16. Для остальных пар ищется сближение осей до OD с двусторонним запасом аппроксимации. Это численно обоснованная проверка данного класса кривых, не формальная сертификация GEOS.

Морфология выведена из порядка поворотов и координат направленных прямых. Поддержана конкретная грамматика CW-in/CCW-out и двух внешних возвратных проходов; отражения/повороты осей приводятся к каноническому виду. Иной корректный шаблон может не поддерживаться этим checker. Он не объявляется физически невозможным.

**Шаг имеет явно ограниченную семантику.** Чередование прямых уровней проверяется численно на200/400 мм. Дополнительные нормальные сечения разбиваются по всем концам прямых и границам BOX-зон. Вне переходов соседние прямые должны иметь p200. В поворотах используется bbox фактической дуги, расширенный на p/2, а вдоль перпендикулярных проходов — аналогичная ограниченная ориентационная полоса. После исключения ориентационных полос кусок сечения перед учётом поворотов ≤3p; остатки вне BOX-зон ≤p. Это не утверждение о постоянном offset200 на дугах. Общие coverage/OD-проверки действуют и внутри исключённых из exact-pitch зон.

Review обнаружил реальный false PASS старой версии секционного checker: единственное сечение через перпендикулярную линию скрывало gap600. Добавлены все границы зон как события; контрпример сохранён и теперь FAIL. Для прямоугольных BOX-зон состояние сечения постоянно между этими событиями. Сам STEP-контракт уточнён до этой ограниченной грамматики; численные исходные пределы не менялись.

## Испытания и независимая проверка

- **17 тестов checker прошли.** Положительные: ручная улитка, сдвиг, поворот90°, отражение. Отрицательные: смещённый конец, непрерывная конструкция R50, повтор, разрыв, obstacle20, коллизия дуги со стеной, OD-contact15 без пересечения осей, змейка вместо улитки, неверный шаг с подложным spacing evidence, диагональ. Порог OD16 даёт Indeterminate именно правила clearance; общий статус этого специально сконструированного кейса Fail по другим ограничениям. Есть детерминизм и регрессия найденного review-контрпримера.
- **5 тестов экспериментального шаблона прошли**, включая семь значений ширины, границы поддержки, сохранение пользовательского входа, предел длины и повторяемость.
- Независимый агент read-only повторил 15 сохранённых геометрических кейсов. Другим расчётом с sagitta0,001 мм подтвердил reference length58 198,229715 мм, R100, coverage100%, верхнюю оценку241,285467 мм. Его review выявил и помог устранить описанный false PASS.
- Claude Code CLI найден и вызван для ограниченного read-only review. Аудит **не состоялся**: `Failed to authenticate: OAuth session expired and could not be refreshed`. Ответ CLI приложен; это не успешная Claude-проверка и не прохождение owner-публикационного gate.

## UFH Designer: что удалось адаптировать

Закреплён прежний commit `bafc690f340943f6e04f9bf9a34b2c1e268d39e0`. В исходный TypeScript при транспиляции добавлены только две диагностические вставки: сохранение аргументов arcPts и используемого преобразования координат. В рабочем checkout исходник не менялся. Из трассы вызовов выбраны дуги, последовательности точек которых полностью совпадают с финальным результатом, включая обратный порядок. Кривые не подгоняются по трём точкам. Сохранены 23 реальные дуги; исходный массив точек побайтно совпал с прежним результатом.

Это снимает прежний Indeterminate радиуса **для данного инструментированного прогона**: R и касательные проходят. Исходные upstream tests не менялись и повторно без необходимости не запускались; прежний результат76/81 остаётся в журнале R2.

Попытка терминального адаптера: виртуальная область4000×2800, перенос(100,100), явно построенные подводящие линии/дуги и укорочение последнего прямого участка. Физический допустимый пол и концы остаются исходными. Такая виртуальная рамка сама по себе не является разрешённой областью; окончательные кривые проверяются по реальному fixture.

| Вариант | Концы/G1/R | Coverage250 | Самопересечения / OD | Итог |
|---|---|---|---|---|
| Исходный UFH с восстановленными из trace дугами | Концы/направления Fail; G1/R Pass | Max-gap Fail | Проверки проходят | Fail |
| Терминальный адаптер | Проходят | Проходит | Наложение по y300; clearance Fail | Fail |
| Ручной эталон | Проходят | Проходит | Проходят | Synthetic Pass |

Причина отказа выбранной адаптации конкретна: существующий верхний проход занимает зарезервированную полосу обратки. Значит, недостаточно добавить концы снаружи — нужно менять внутреннюю раскладку и центральную схему. Не перебирались все возможные адаптации; не доказано, что ограниченный patch upstream невозможен. BUILD выбран как ограниченное инженерное решение с уже проверенным малым шаблоном, а не как вывод о непригодности всего репозитория.

## M1b: граница собственного шаблона

`template.py` строит уровни циклом и материализует точные дуги. Поддержка: осевой прямоугольник с origin(0,0), ширина4000..5000 мм, высота3000 мм, p200, OD16, Rmin80..100, заранее заданные supply=(200,100) и return=(width−200,2900), обе касательные(+1,0). Реальные дуги R100. Препятствия, другая высота, p100 и другие концы дают Unsupported; концы не сдвигаются к результату.

Каждый возвращаемый кандидат проходит независимый validator. Статусы: `ValidSynthetic`, `Unsupported`, `NoFeasibleCandidateFound`, `ValidationIndeterminate`, `InvalidInput`. Превышение лимита длины не называется ProvenInfeasible. Результат не записывается в HomeAura или CAD.

Проверены ширины4000;4000,001;4250;4500;4750;4999,999;5000 мм. Это выборочные испытания диапазона, не формальное доказательство всех вещественных ширин. Защитой каждого конкретного результата служит повторная валидация при generate.

## Адресный поиск и дальнейшая работа

Поиск ограничен дугами, сшивкой и независимыми геометрическими проверками. Документация [Shapely](https://shapely.readthedocs.io/en/stable/manual.html) подтверждает аппроксимационную природу buffer; поэтому отчёт использует явные границы ошибок. Найденный [cpp_SpiralFloorHeating](https://github.com/marcin-filipiak/cpp_SpiralFloorHeating) описывает оценку длины прямоугольной раскладки и имеет GPL-3.0; он не дал основания заменить текущий точный line/arc-стенд. Код из него не переносился. [UFH Designer pinned source](https://github.com/ArendJanKramer/underfloor-heating-designer/blob/bafc690f340943f6e04f9bf9a34b2c1e268d39e0/src/geometry/spiral.ts) остаётся полезным кандидатом/источником алгоритмических идей.

Следующая предметная работа — отдельный контракт для более строгого max-gap200 и зоны100/200 с допустимым R80-переходом. Текущий synthetic Pass нельзя использовать как его golden. Реальные C05/C06 остаются отдельной веткой с неизвестными проверенными входами. До CAD/owner-публикации нужны восстановленный доступ Claude и полный предусмотренный owner policy пакет; этот эксперимент его не подменяет.

## Артефакты

`m1a-v2/`: reference и checker, тесты/журналы, template, исходные и адаптированные UFH line/arc JSON, воспроизводимая instrumentation, сравнение PNG/SVG, BOX-зоны, manifest и инструкция воспроизведения. R2 сохраняется как история; текущие выводы находятся в этом документе.
